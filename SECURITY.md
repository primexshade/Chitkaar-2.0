# Security Policy

## Reporting a Vulnerability

Do not publicly disclose security vulnerabilities before they have been
reviewed and addressed.

Security issues should be reported privately to the project maintainers.

## Never Commit

Never commit:

- API keys
- Passwords
- Authentication tokens
- Private keys
- Database credentials
- Production secrets
- `.env` files containing secrets

## Security Principles

Chitkaar 2.0 should prioritize:

- Secure authentication
- Server-side authorization
- Input validation
- Safe form handling
- Secure environment variables
- Dependency updates
- Least-privilege access
- Protection of user-submitted information

## User Data

Volunteer, event, contact, and donation-related information should be
treated as sensitive application data and handled appropriately.

## Dependencies

Dependencies should be kept reasonably current and reviewed before major
upgrades.
